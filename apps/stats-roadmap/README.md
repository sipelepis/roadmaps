# Statistics Roadmap

The statistics and probability roadmap in the same shell as the other roadmaps: 20 modules laid out as a dependency graph, in five stages. It starts with samples and probability rules, goes through distributions, estimation, intervals and tests, and ends with A/B tests, drift detection and error bars on evals. Each module has an article, a live Python playground, and exercises with tests that run in the browser through [Pyodide](https://pyodide.org).

The runtime is CPython with the standard library only. No numpy, scipy or pandas. All data is synthetic and generated by code the learner can read, so the true answer is always known.

Stages, in graph order:

1. Foundations
2. Probability and data
3. From samples to estimates
4. Inference
5. In production

Pages: `#/` roadmap graph · `#/learn` module index · `#/<module>` article + playground + exercises · `#/exercises` every problem with status filters · `#/exercise/<module>/<n>` a single problem with prev/next · `#/reference` the reference pages (`src/content/reference.md`).

```sh
npm run dev      # http://localhost:5173
npm run build    # static site in dist/
npm run check    # tsc --noEmit
npm run verify   # every playground and starter through the page's own harness under local python3
npm run verify -- --solutions ../../.solutions/stats-roadmap   # plus every reference solution, under two hash seeds
```

`npm run verify` needs `python3` on the path. It runs each playground, checks that each starter runs and fails its tests, and reports any exercise whose starter already passes. The `--solutions` form also runs every reference solution and fails the exercise if one of them errors, fails a test, or takes more than a second.

## Adding a module

1. Add a node to `src/graph.ts` (`id`, short `label`, `level` = row in the graph, `deps`).
2. Create `src/content/<id>.md`:
   - `# Title`, then the article.
   - One ```` ```python playground ```` block becomes the live editor.
   - Under `## Exercises`, each `### N.` heading (for example `### 1. Relative error`) has a description, a ```` ```python starter ```` block, and a ```` ```python test ```` block.
3. Tests are plain `test_*` functions using `assert`; a docstring becomes the label. The starter and the tests run in one namespace, so tests call the learner's functions directly. A problem passes when the code runs without error and every test passes. Helpers a learner should not have to rewrite go in the starter above the `...`.

After the starter and test blocks, each exercise can list:

- `#### Uses`: links to the article sections it relies on, as `[Module › Section](#/<module>/<section-slug>)`. Uses links may only point to this module or modules it builds on.
- `#### Hints`: revealed one at a time.
- `#### Tips` and `#### Docs`: optional. Docs links point to official Python documentation.

`npm run check:refs` from the repo root enforces the Uses rule, so no exercise needs something the learner hasn't reached.

## Test rules

- Randomness only through a seeded generator: `rng = random.Random(seed)`, passed into the function that needs it. Never the module-level random functions.
- Exact expected values only where they come from a `rng.random()` sequence, since Python guarantees that sequence for a given seed.
- Any other random result is checked by a property (a range, a count, an ordering, a round trip) or by a tolerance band.
- Floats are compared after `round(got, 9)` or formatted as `f'{x:.9g}'`, never with `==` on raw computed floats.
- Never use the built-in `hash` for anything a test depends on. Its values change with `PYTHONHASHSEED`, and the verify step runs solutions under two hash seeds to catch it.

## Reference solutions

Reference solutions live outside git, in `.solutions/stats-roadmap/<id>.<n>.py`, at the monorepo root. One file per exercise, numbered the same as the `### N.` heading. They are not published with the site, and `npm run verify -- --solutions ../../.solutions/stats-roadmap` is how they are checked.

## Deploying

Vercel project `stats-roadmap`, root directory `apps/stats-roadmap`, live at https://stats-roadmap.vercel.app. Pushing `main` redeploys it. See the root `README.md` for the deploy steps shared by all roadmaps.
